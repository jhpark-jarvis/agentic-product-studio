# Agent collaboration

## Why documents live in the repository

대화 세션은 짧고 휘발될 수 있습니다. 중요한 사실을 채팅 기억에만 두면 다음 Agent가 이미 끝난 결정을 다시 조사하거나 서로 다른 전제를 사용할 수 있습니다. 이 프로젝트는 결정, 제약, 완료 조건과 다음 작업을 저장소 문서에 남겨 컨텍스트 손실을 줄입니다.

## Source-of-truth order

1. 현재 사용자가 명시한 목표와 승인
2. 저장소의 설계·운영 문서
3. 애플리케이션 API와 데이터 모델
4. 구현 코드와 테스트
5. 오래된 대화 요약

충돌이 있으면 최신성이 높은 근거를 확인하고, 결과를 다시 문서화합니다.

## Recommended loop

1. 작업과 관련된 문서만 선별해 읽습니다.
2. 코드·API·데이터로 현재 상태를 검증합니다.
3. 되돌리기 어렵거나 제품 방향을 바꾸는 선택은 사람에게 요청합니다.
4. 구현 후 테스트와 빌드를 실행합니다.
5. 무엇이 바뀌었고 무엇이 남았는지 문서에 기록합니다.

## Human decision gates

아래 항목은 Agent가 임의로 확정하지 않습니다.

- 공개 범위와 권한 정책
- 실제 사용자 데이터의 이동·삭제
- 외부 서비스 비용이나 계약을 만드는 선택
- 제품 정체성, 법적 조건과 라이선스
- 일정·품질·유지보수 방식이 크게 달라지는 아키텍처 분기

## Context recovery checklist

- `README.md`에서 제품 목적과 실행 방법 확인
- `docs/architecture.md`에서 시스템 경계 확인
- Git 로그에서 최근 변경 흐름 확인
- 테스트로 현재 동작 확인
- 미완료 작업은 별도 문서에 상태·근거·다음 행동 기록
